# AI usage

## Tools and scope

OpenAI Codex assists with requirements review, implementation planning, code, tests, and review. The installed Awwwards skill guides the frontend concept, typography, layout and production visual verification. Its three-concept exercise and selected classroom-capacity direction are recorded in `DESIGN.md`. Context7 was queried through its remote MCP endpoint for official EF Core/Npgsql documentation and for React Context, TanStack Query cancellation and Axios AbortSignal guidance.

## Checks and corrections

- The dependency review found that the requested `react-rangeslider` peer versions exclude the required modern React versions. The planned replacement is Radix Slider.
- Publisher metadata showed that selecting every dependency's latest major would conflict with the Next.js lint toolchain. Compatible versions are pinned and verified through installation, builds, and tests; ESLint 9 is retained for compatibility despite its upstream end-of-life warning.
- Context7 confirmed that EF migrations should use `MigrateAsync` without a surrounding application transaction or `EnsureCreated`. Reservation operations will use their own explicit, parameterized PostgreSQL transactions.
- The initial backend scaffold passed locked restore, a Release build with zero warnings/errors, formatting verification, and an HTTP liveness smoke check. Feature tests are added with their respective features.
- The initial domain model passed 27 unit cases on .NET SDK 10.0.403, including strict string identifiers, expiry boundaries and terminal/idempotent lifecycle transitions. Capacity and ownership were verified in the subsequent application/database feature tests described below.
- The database foundation passed fresh and repeated migrations, HTTP readiness, a Docker Release build, and both real PostgreSQL schema tests. The exact staged source was verified separately from prepared endpoint work. WSL's idle shutdown interrupted an initial run; keeping the WSL session active restored stable Docker verification. No cloud database was accessed.
- Class endpoint integration tests caught an AI implementation error: adding a second `traceId` through `ControllerBase.Problem` made expected 400/404 responses become 500. Updating the existing extensions fixed it. Review also corrected a test that unnecessarily required a relative Location URL. The final Docker suite passed 27 unit and five integration tests, with no skips.
- Reservation implementation passed independent concurrency review and the Docker suite: 27 unit and 12 integration tests, with no skips. Across two API processes, 100 requests for 10 seats produced exactly 10 holds; 100 requests for one student/class produced one hold. Stored allocations and public counts were checked. The local connection pools were bounded to leave PostgreSQL connection headroom under that workload.
- Confirmation passed 27 unit and 17 integration tests in Docker. One hundred concurrent owned confirmations across two API processes all succeeded with one stored allocation. A database-observed lock-wait test held confirmation until after expiry and verified rejection, exercising the fresh-clock requirement rather than merely checking sequential expiry.
- Cancellation passed the Docker suite of 27 unit and 23 integration tests. Checks include empty 204 responses, ownership before idempotency, terminal states, reapplication, 100 concurrent repeated cancellations, and ten two-process confirmation/cancellation races with exactly one winning transition and consistent stored/public counts.
- Automatic expiry passed independent lock-order review and 27 unit plus 27 integration tests in Docker. A dedicated three-second hold server proved persisted expiry through database polling without admission requests; tests also checked terminal states, a skipped locked class, and queued mutations crossing expiry. Review corrected the lock-observer test helper to follow PostgreSQL's chained blockers instead of assuming every waiter is blocked directly by the test connection.
- Final backend review found two gaps: PostgreSQL rejects NUL inside names, and direct API execution did not recognize the assignment's literal `HOLD_DURATION_SECONDS` variable. Shared validation now rejects NUL with 400, and the literal variable takes precedence over the nested option. The Docker suite passed 29 unit and 29 integration tests, including configured-duration precedence and confirmed-student duplicates with spare capacity.
- API restart, startup recovery with database-only observation, and ordinary Compose down/up persistence passed against local PostgreSQL; synthetic fixtures were removed afterward. Default duration was 600 seconds. Invalid zero duration failed startup, while migration/health-check modes remained independent. A current NuGet audit reported no vulnerable direct or transitive packages in the six backend projects.

- The frontend foundation uses the official Next.js scaffold, local Manrope fonts, Bootstrap and colocated Sass modules. Context7 supplied version-specific Route Handler, standalone deployment, Context, query cancellation and Axios guidance. The production Docker build, lint and type checks passed. A real PostgreSQL/API proxy check covered GET/POST/DELETE, student headers, Problem Details, rewritten Location headers and empty 204 responses. Chromium checks at 1440px and 390px found no horizontal overflow, page errors or serious/critical axe violations; skip links, the designed 404 and PNG metadata routes passed.
- The initial frontend audit found a transitive minimatch vulnerability. A scoped override under typescript-estree upgraded it to 11.0.5, beyond the fixed version in [GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249). The subsequent audit reported zero vulnerabilities, and lint, type checks and the production Docker build passed with that lockfile.

- Student identity passed an isolated staged-source production Docker build and 11 Playwright checks, covering leading zeros, strict ASCII validation, reload recovery, malformed/blocked storage, cross-tab changes, phone use, and cancellation/cache isolation. Visual review caught missing page gutters and cramped phone navigation; both were corrected and rechecked at 1440px/390px with zero serious/critical axe violations, page errors or overflow. A test locator was corrected to distinguish the application alert from Next.js's route announcer. Context7 supplied React Hook Form, hydration and query cancellation guidance.

- The live catalogue passed indexed-source native and Docker production builds, eight focused catalogue/navigation checks, and the combined 19 identity/catalogue checks against Docker. Controlled-fixture visual checks at 1440px/390px found no overflow, page errors or serious/critical axe violations. Review corrected GSAP reduced-motion boundary restoration and added a keyboard-accessible phone menu. Context7 supplied polling, AbortSignal and GSAP cleanup guidance. A full WSL disk interrupted Docker verification; after the owner freed space and WSL restarted, the checks resumed without resetting application data.

- Class creation passed its isolated indexed-source Docker build and all 11 creation/navigation checks. Tests cover trimmed names, UTF-16 length and NUL boundaries, positive integer capacity, pending controls, malformed success responses, 400/409/502 retry paths, and phone keyboard use. Desktop/phone visual checks found no overflow, page errors or serious/critical axe violations. A navigation failure was rechecked separately and in the complete passing run after restoring the local server. Context7 supplied Zod, resolver and mutation invalidation guidance.

- Reservation/details passed its indexed Docker build and 16 reservation/catalogue checks. Coverage includes captured identity headers, conflicts, late responses after identity changes, malformed timestamps and monotonic server-clock expiry with transport latency. A real UI flow created a class, saved a leading-zero identifier, reserved a place, verified ownership and checked changed seat counts in PostgreSQL-backed responses. Desktop/phone axe review caught Bootstrap's RGB link variable retaining its default blue; defining the matching palette RGB variables fixed contrast. The repeated real flow and both axe/overflow checks passed; only its synthetic class and holds were removed afterward.

- Mock fee confirmation and cancellation passed an indexed Docker build and all 22 action/reservation checks. Tests cover empty 204 cancellation, success/terminal feedback, ownership, 403/409/502 recovery, opposing-action locks, expiry while a dialog is open, and identity changes during a request. A real UI confirmation persisted after reload and changed the stored/public seat summary once. Desktop/phone detail and dialog axe checks passed; synthetic data was removed. SweetAlert2 loads only when requested, and operation tokens prevent a late import from opening a stale dialog after navigation or identity changes.

- History and filtering passed the indexed Docker build and all 19 history/filter/catalogue checks. Tests cover current-student headers, cross-tab changes with delayed responses, filter reset, inclusive dates, status/class combinations, debounced search, both slider bounds, polling and keyboard help. Pointer testing confirmed React Select's visible control works; tests were corrected to avoid its hidden keyboard focus input. Another selector was narrowed because HTML output also has an implicit status role. Controlled-fixture desktop/phone axe and overflow checks passed for history and the filtered register.

- Independent PDF review caught the literal requirement for a birth-registration input at the top of each page. A compact shared Context-backed input now satisfies it while retaining the dedicated management page. Its indexed Docker build, 18 identity/navigation checks, and desktop/phone home/student axe and overflow checks passed. Feedback is scoped to the saved identifier so a change or clear elsewhere cannot leave an old success notice visible. Existing storage assertions were scoped to the main form after the new top control added its own notice.
